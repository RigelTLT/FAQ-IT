# Лаборатория Python, BI, AI и 1С

Стартовый комплект работает на Python 3.12+ без внешних пакетов. Все данные вымышленные. Mock показывает **собственный контракт HTTP feed**, не является реальной 1С и не реализует стандартный OData. Практика с метаданными настоящей конфигурации остаётся отдельным заданием курса.

## Первый запуск

Откройте терминал в `data-ai/lab`:

```powershell
python generate_data.py
python -m unittest -v test_pipeline.py
python pipeline.py --db training.sqlite
python pipeline.py --db training.sqlite
```

Первая загрузка: `new_events=9`, `total_kopecks=13000`. Повтор: `new_events=0`, итог остаётся 13000. ORG1 — 10000 копеек, ORG2 — 3000. Активных строк три. В состоянии также остаются отменённая и удалённая записи для контроля версий.

Движение данных: A=10000, A2=5000, B=7000, возврат=-2000, затем A v2=12000, B удаляется, приходит поздняя LATE=3000, A2 снимается с проведения, поздняя A v1 игнорируется. Итог: 12000 − 2000 + 3000 = 13000. `sample/controls.json` фиксирует независимый ручной контроль.

## HTTP-источник

```powershell
python mock_onec.py --port 8011
```

В другом терминале:

```powershell
Invoke-RestMethod 'http://127.0.0.1:8011/metadata'
Invoke-RestMethod 'http://127.0.0.1:8011/changes?cursor=0&limit=3'
Invoke-RestMethod 'http://127.0.0.1:8011/changes?cursor=3&limit=3&cutoff=9'
Invoke-RestMethod 'http://127.0.0.1:8011/changes?cursor=0&duplicate=1'
```

Читайте до `has_more=false`, передавая `next_cursor` и первоначальный `snapshot_cutoff`. `duplicate=1` повторяет событие в ответе. `fail=429` или `fail=500` возвращает управляемый отказ. Сервер слушает только localhost, не имеет auth/TLS и не предназначен для рабочего размещения. Завершение — Ctrl+C.

**Задание:** реализуйте HTTP-extract с timeout, ограниченным retry, сохранением raw-страниц и manifest, затем подключите к ядру. `pipeline.py` читает полный подтверждённый файловый пакет; он не притворяется готовым HTTP-коннектором. При загрузке постранично сначала подтвердите полноту диапазона, иначе checkpoint может перескочить неполученные события.

## Сбой и восстановление

```powershell
python pipeline.py --db recovery.sqlite --fail-before-commit
python pipeline.py --db recovery.sqlite
```

Первая команда намеренно завершается исключением. В `inbox`, `sale_state`, `checkpoint`, `mart_daily` не должно быть частичных записей. Вторая восстанавливает итог 13000. Тест проверяет это автоматически, а также повторы, версии и независимость источников. Для проверки сбоя **после** commit до ACK добавьте транспортный consumer: его нет в минимальном файловом примере.

## Перенос в PostgreSQL

`schema_postgres.sql` создаёт учебную схему и view. Перенесите запись на SQLAlchemy, используя PostgreSQL dialect upsert, параметры и транзакцию. Не запускайте DDL в рабочей БД. В учебном ядре mart пересобирается целиком; затем реализуйте пересчёт затронутых периодов и сравните результат с полной пересборкой.

Файлы `sales.csv` содержат отдельный грязный набор для pandas/Polars: неверную дату, пропуск и дубль. Он не равен журналу событий и не предназначен для сверки 13000. `sample/documents` и `rag_questions.json` — маленький RAG-корпус; расширьте его до 30 контрольных вопросов, добавьте версии, фильтры прав и удаления.

## Ограничения стартового ядра

Это учебное текущее состояние, без SCD2 клиентов, миграций, сетевого retry, orchestration, BI, API и моделей. Вы реализуете их в соответствующих уроках. SQLite подтверждает локальную логику; конкурентность PostgreSQL, настоящий OData, объекты УТ/УНФ/Бухгалтерии и неизвестной АТК проверяются отдельно. Полнота и checksum проверяются для полного учебного пакета. Контракт предполагает неизменяемые события с уникальным ID и возрастающими версиями сущности; в реальном адаптере добавьте контроль конфликтующего payload при одинаковой версии/ID.
