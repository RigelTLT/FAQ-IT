## Сквозной пример

В учебном проекте две организации, «Север» и «Волга». На первой выгрузке у «Севера» доставлено одно из двух отправлений. После обработки новой версии статуса доставлены оба. Повтор пакета сохраняет результат. По этим же данным строятся сводка, HTTP-ответ и проверки доступа. Обращение «Где статус?» связывает кабинет с маршрутизацией и поиском по регламенту.

## Как проходить

Материалы Яндекс Практикума использованы как ориентир для последовательности «объяснение → разбор → самостоятельная задача → проект спринта». В каждом уроке прямо на странице есть задача, понятия простым языком, входные данные, ход решения и задание с ответом. Каждый этап завершает практикум с порядком работы и критериями. Курсы Harvard CS50P, Google ML Crash Course и Hugging Face LLM Course и официальные справочники указаны рядом с темами для углубления. SQL-примеры идут вместе с DWH. FastAPI используется в сквозном проекте, пример Django доступен для справки.

1. До запуска найдите точку входа, проследите один объект через функции и предскажите вывод.
2. Запустите пример, сравните вывод с прогнозом, измените вход и проверьте отказ.
3. Объясните границы данных, бизнес-правил и внешних зависимостей. Напишите замечание к PR с проверяемым последствием.
4. Сохраните артефакт и команду воспроизведения. Используйте [требования к тимлиду](index.html#/requirements) для подготовки к защите.

## Лаборатория и проект

[Лаборатория](lab/README.md) работает на Python 3.12+ без сторонних пакетов. Начните с `shipments.csv` и `shipment_app.py`. Команда `python data-ai/lab/shipment_portal.py` показывает сквозной пример. Дополнительный `shipment_api.py` даёт HTTP-доступ к тому же отчёту. Затем расширьте контур до PostgreSQL, Prefect, BI, обученной классификации и RAG. Пример с продажами и возвратами доступен как дополнительная лаборатория. Примеры с библиотеками запускайте в учебных окружениях с зафиксированными версиями.

Проект использует синтетические данные. АТК требует подтверждения точной конфигурации, релиза, владельца и метаданных. Доступ к реальным 1С и CRM, коммерческий SLA и качество AI в рабочем процессе проверяются на следующих этапах внедрения. Требования о стаже и опыте руководства подтверждаются рабочими примерами.
